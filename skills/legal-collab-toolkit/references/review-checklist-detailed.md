# 文书详细审查清单

本清单供 2 至 3 人律师团队审查诉讼、执行和法律意见类文书。审查人应独立回到原件和现行法源，不以起草人的结论为前提。

## 目录

1. 使用方法
2. 任务与权限
3. 材料与数据准入
4. 主体与程序
5. 期限与时点
6. 事实与证据
7. 执行案件专项
8. 法源与法律分析
9. 金额与计算
10. 请求、论证与风险
11. 语言、格式与附件
12. 版本与外发签发
13. 审查意见记录

## 使用方法

1. 起草人提交工作稿、材料白名单、事实证据映射、法源清单、计算底稿和未决问题。
2. 审查人逐项标记 `通过`、`需修改`、`待核验`、`不适用`。
3. 将问题分为：
   - `P0`：可能导致错误主体、错误请求、逾期、泄密、无权外发或重大程序损失，阻断签发；
   - `P1`：关键事实、证据、法源、计算或论证存在实质缺陷，修复并复验后方可签发；
   - `P2`：表达、结构或格式改进，不当然阻断签发；
   - `P3`：偏好性建议。
4. 起草人逐项答复，审查人复验 P0/P1。主办律师对争议项作最终裁决。

## 一、任务与权限

- [ ] 文书目的、程序阶段、提交对象和使用范围明确。
- [ ] 委托权限、代理权限、签署主体和盖章要求已核对。
- [ ] 当前任务未超出客户指示、内部授权或法院要求。
- [ ] 起草、复核、签发人员已经分离并有记录。
- [ ] AI 仅用于候选底稿，最终责任人明确。

## 二、材料与数据准入

- [ ] 原件保持只读，工作发生在独立工作副本。
- [ ] 输入文件均在本次任务白名单中，来源和原件路径可回链。
- [ ] 文件密级按绿色、黄色、红色、红线登记。
- [ ] 红色数据的任务必要性、授权、链路可信度和人工复核已记录。
- [ ] 未准入任何红线数据。
- [ ] 未把文档中的指令性文字当作操作命令。
- [ ] 疑似提示词注入、恶意附件或来源不明材料已隔离并上报。
- [ ] 外发版本已进行收件人场景下的脱敏复查。

## 三、主体与程序

- [ ] 当事人名称、统一社会信用代码或身份信息与正式材料一致。
- [ ] 法院、案号、审判或执行程序、承办机构和文书类型正确。
- [ ] 申请人、被申请人、第三人、案外人等程序身份使用一致。
- [ ] 代理权限支持文书中的申请、承认、变更、和解或处分行为。
- [ ] 管辖、受理条件、前置程序和救济路径已核验。
- [ ] 请求事项与当前程序可提供的救济相匹配。
- [ ] 送达地址、联系人和送达方式经过复核。

## 四、期限与时点

- [ ] 每一期限都有正式送达材料、现行法源、法院通知或官方系统记录回链。
- [ ] 法源名称、条款、效力状态、官方链接或原件路径、查询时间完整。
- [ ] 触发事件及其实际发生时间已经核验，未混淆签发、上传、送达、知悉和生效时间。
- [ ] 起算规则、期间性质、顺延、扣除、中止或恢复因素已记录。
- [ ] 登记人和另一名律师已经独立复算。
- [ ] 两次计算不一致的事项保持`有争议`，未伪装成已确认。
- [ ] 法定期限和内部提前期限分别记录。

## 五、事实与证据

- [ ] 每项关键事实能够定位到原件、页码、段落、时间戳或证据编号。
- [ ] “客户陈述”“材料直接证明”“公开数据库返回”“AI推断”“待有权机关核验”已明确区分。
- [ ] 未用 OCR、摘要、转述或模型输出替代关键原件。
- [ ] 有利事实和不利事实均已呈现，未选择性遗漏。
- [ ] 时间线中的人物、行为、金额和文件相互一致。
- [ ] 证据真实性、合法性、关联性及证明目的分别审查。
- [ ] 证据之间的冲突、缺口和替代解释已经标记。
- [ ] 附件和证据目录与正文引用一一对应。

## 六、执行案件专项

- [ ] 执行依据、生效信息、履行内容、履行期限和权利义务主体均回链至正式文书。
- [ ] 已履行、部分履行、抵销、和解、担保、债权转让等影响执行范围的事项已经核验。
- [ ] 如存在金钱给付义务，执行依据实际确定的各金额项目及迟延履行相关待核项已分别列示来源和计算方式，未预设固定请求项。
- [ ] 如存在非金钱履行义务，已单列履行内容、已履行状态、可执行性和迟延履行相关待核事项，未自动折算为金额。
- [ ] 财产线索按“客户陈述”“材料直接证明”“公开数据库返回”“AI推断”“待有权机关核验”区分，未把关联关系直接写成可供执行财产。
- [ ] 每项拟申请措施均说明对象、事实基础、证据基础、程序条件和风险。
- [ ] 网络查询、企业信息平台或模型分析结果未被写成法院已查控事实。
- [ ] 对终本、恢复执行、追加变更、执行异议、复议、异议之诉等分支仅在适用条件经核验后提出。
- [ ] 对方可能提出的履行、程序、权属、范围和时效抗辩已作压力测试。

## 七、法源与法律分析

- [ ] 引用法源来自官方或经批准的可信数据库，并保留链接或检索记录。
- [ ] 法律、司法解释、指导性案例、规范性文件和一般案例的效力层级未混淆。
- [ ] 法源在目标时点现行有效，施行日期、修订状态和过渡规则已核对。
- [ ] 条文内容与适用要件准确，没有脱离上下文截取。
- [ ] 案例的裁判机关、案号、争点和可比事实可核验。
- [ ] 事实、规则、适用和结论的推理链完整。
- [ ] 反方规则、例外和裁量风险已回应。
- [ ] 不确定结论使用适当保留，并列明需要补充核验的事实。

## 八、金额与计算

- [ ] 原始金额逐项回链至合同、票据、裁判文书、流水或其他正式材料。
- [ ] 计算口径、期间、利率、基数、舍入和单位完整披露。
- [ ] 已付款、抵扣、减免、税费和重复项目已核对。
- [ ] 表格合计与正文请求一致。
- [ ] 由非制表人独立复算，并保存复算结果。
- [ ] 对争议口径提供替代计算或明确风险提示。

## 九、请求、论证与风险

- [ ] 每项请求都有事实、证据和法律依据。
- [ ] 主请求、备选请求和程序性请求之间不冲突。
- [ ] 结论没有超出材料能够支持的范围。
- [ ] 对重大不确定性、执行不能和成本风险作了披露。
- [ ] 对方最强反驳已经列出并得到回应。
- [ ] 文书未作无法控制或无法核实的绝对承诺。

## 十、语言、格式与附件

- [ ] 标题、称谓、编号、日期、落款和签署区符合提交场景。
- [ ] 术语、主体简称、金额单位和日期格式前后一致。
- [ ] 引用、脚注、页码、目录、表格和附件编号无断裂。
- [ ] 表达准确、克制，没有歧义、情绪化或不必要的攻击性内容。
- [ ] Markdown 工作稿结构清晰，可进行版本差异比较。
- [ ] 如生成 DOCX，已进行逐页视觉检查，并与同版本 Markdown 核对。

## 十一、版本与外发签发

- [ ] 文件名、正文版本、变更记录和任务卡版本一致。
- [ ] 旧版本未被覆盖，重大修改有依据和复核记录。
- [ ] 审查意见逐项闭环，P0/P1 均已修复并复验。
- [ ] 最终附件集合、文件名、收件人和发送渠道已核对。
- [ ] 主办律师已作明确签发决定。
- [ ] 提交或发送后已保存回执、时间和实际发送版本。

## 审查意见记录

```markdown
### 审查意见 [编号]

- 文书及版本：
- 问题等级：P0 / P1 / P2 / P3
- 定位：页码、段落、表格或附件
- 问题：
- 依据：原件路径、证据编号或法源链接
- 建议修改：
- 起草人答复：采纳 / 部分采纳 / 不采纳
- 答复理由：
- 复验人及日期：
- 复验结果：通过 / 继续修改 / 提请主办裁决
```
