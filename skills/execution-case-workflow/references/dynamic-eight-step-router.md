# 执行案件动态路由

## 目录

1. 四个结构位置
2. 前端判断
3. 信息入口
4. 条件分支
5. 团队支撑
6. 分支候选表
7. 路由示例

本路由把八步法作为案件判断和任务选择框架，不把它写成八个必须依次完成的动作。

## 一、四个结构位置

| 位置 | 对应能力 | 何时出现 | 默认结果 |
|---|---|---|---|
| 前端判断 | 案件初筛 | 谈案、接案评估、补材料复评 | 接案评估草案和承接条件 |
| 信息入口 | 线索收集 | 首批材料、正式材料、新材料、客户或法院反馈 | 信息分层、缺口和核验任务 |
| 条件分支 | 财产调查、数据分析、扩大主体或责任财产、财产处置、异议应对 | 具体事实与待核要件出现 | 少量候选方向和合法下一动作 |
| 团队支撑 | 项目记忆、分工、反馈和动态调整 | 贯穿全案 | 任务责任、回执和版本更新 |

每次只进入当前事实支持的位置。没有触发条件时，不为追求形式完整而展开全部分支。

## 二、前端判断

前端判断回答：

- 谁准备委托，案件地位和权利来源是什么。
- 执行依据、生效、履行和程序状态目前清楚到什么程度。
- 客户真正希望得到什么。
- 有哪些支持因素、制约因素和主要风险。
- 客户所称财产或规避执行行为有什么依据。
- 承接前还需要补什么、核什么、由谁决定。

输出只是一份接案评估草案。AI 不作最终承接决定，不使用执行成功率或未经核验的回款统计。

## 三、信息入口

把每批信息分为：

- 正式材料直接载明或支持的内容；
- 客户陈述；
- 公开数据库本次实际返回；
- AI 推断；
- 待有权机关核验；
- 缺失、冲突或无法读取；
- 下一轮合法核验动作。

信息入口贯穿谈案和正式办案。新材料进入时只改变被它实际影响的记录，不重做全案。

## 四、条件分支

### 1. 财产调查

**触发事实**

- 出现可识别的账户、房产、车辆、设备、股权、债权、知识产权、保险或其他权益线索；
- 存在明确主体、对象、来源和合法查询路径；
- 需要核实历史线索的当前状态。

**可以输出**

- 当前依据和说明范围；
- 权属、负担、时点和可控制性缺口；
- 法院申请、律师调查令、客户补件、公开查询或其他合法核验任务；
- 责任人、顺序、预期回执和停止条件。

**停止条件**

- 主体或对象无法识别；
- 查询未授权或会触碰红线数据；
- 连接器不可用且没有人工路径；
- 历史信息被误当成当前状态。

不得声称 AI 已完成法院查控、登记核验或控制措施。

### 2. 数据分析

**触发事实**

- 已经合法取得银行流水、支付记录、交易台账或其他交易数据；
- 数据范围、取得方式、用途和保存位置已经获准；
- 数据质量足以进行有限分析。

**可以输出**

- 交易时间、对手方、金额、频次和余额字段的结构化整理；
- 稳定收入、对外债权、资产购买、异常处分或活动区域的候选模式；
- 支持证据、可能反证、数据缺口和下一核验动作。

**停止条件**

- 数据来源不明、范围越权或含红线信息；
- OCR 或表格解析错误无法排除；
- 只有零散截图却要求形成完整资金结论。

模式分析保持 `AI推断`，不得直接写成隐匿、转移财产或有能力执行的事实。

### 3. 扩大主体或责任财产

**触发事实**

- 出资、股权转让、减资、抽逃、注销、合并、分立、分支机构或主体承继资料出现；
- 债务人对第三人可能享有债权；
- 出现放弃债权、无偿处分、明显异常对价或其他影响债权实现的交易事实；
- 存在第三人承诺、担保或其他责任来源材料。

**可以输出**

- 追加或变更被执行人候选；
- 代位权或撤销权候选；
- 其他另诉或责任财产候选；
- 每一方向的触发事实、待核要件、证据缺口、反证、程序和官方法源状态。

**停止条件**

- 只有工商关联关系，没有责任要件事实；
- 只有客户推测或异常感受，没有交易、出资或权利材料；
- 现行官方法源和程序未核验；
- 律师尚未作具体程序决定。

不得写成“股东变更即应追加”“关联交易即构成转移财产”。

### 4. 财产处置

**触发事实**

- 已有正式查封、冻结、扣押、评估、拍卖或其他控制和处置材料；
- 财产对象、权属、占有或负担可以识别；
- 需要跟进评估、公告、竞买、价款或交付。

**可以输出**

- 财产现状、权属和负担待核清单；
- 处置障碍、所需申请、责任人和时间；
- 评估、腾房、公告、竞买、成交、价款和交付的跟进任务；
- 价值和成本的待核项。

**停止条件**

- 只有财产线索，没有正式控制材料；
- 历史回执无法证明当前查封或冻结状态；
- 要求使用固定折价比例或承诺处置结果。

### 5. 异议应对

**触发事实**

- 收到执行行为异议、案外人异议、复议、异议之诉材料或相关裁定；
- 已有租赁、所有权、占有、优先权、共有或其他可能阻碍处置的具体材料；
- 某项执行措施面临可以具体描述的程序或权属争议。

**可以输出**

- 异议类型候选和程序位置；
- 对方主张、现有证据、反证、缺口和待核法源；
- 申请执行人一方的候选回应和证据任务；
- 是否需要另行评估继续执行、担保、复议或诉讼等问题。

**停止条件**

- 没有具体异议事实或材料；
- 依赖旧课件的固定期限或旧司法解释结论；
- 需要律师选择诉讼策略或对外提交但尚未 G2、G3 放行。

### 6. 拒执相关候选

拒执不是八步法中的固定必经分支，但客户经常提出。只有出现与履行能力、执行义务、拒绝履行行为和严重情节相关的具体事实材料时，才形成候选评估。

统一列明：

- 哪些事实由正式材料支持；
- 哪些只是客户陈述或 AI 推断；
- 构成要件和程序仍缺什么；
- 现行司法解释、意见和受理路径是否核验；
- 律师需要决定的移送、控告或其他动作。

不得因存在未履行、限高或财产线索就直接写成构成拒执。

## 五、团队支撑

每个被触发的分支都回到同一份项目任务清单：

| 任务 | 对应事实或线索 | 责任人 | 所需权限 | 预期正式回执 | 建议顺序 | 停止条件 | 项目记忆更新 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |

客户反馈、法院反馈和律师决定作为新批次进入，不在多个独立对话里形成互相冲突的版本。

## 六、分支候选表

```markdown
# 执行专项候选评估

| 候选方向 | 触发事实 | 当前来源状态 | 待核法律要件 | 现有支持材料 | 可能反证 | 关键缺口 | 程序路径 | 官方法源状态 | 律师决定 |
|---|---|---|---|---|---|---|---|---|---|
|  |  | 材料直接证明 / 客户陈述 / 公开数据库返回 / AI推断 / 待有权机关核验 |  |  |  |  |  | 已核验并回链 / 待核验 | 待决定 |
```

没有官方法源核验和律师决定，不得把候选表转成确定方案或对外文书。

## 七、路由示例

### 示例 1：只有股东变更公示

触发“扩大主体候选评估”，但只记录公示时间、股东变化和仍缺的出资、转让、责任要件材料。不得直接建议追加。

### 示例 2：客户称设备被低价转走

保留为客户陈述，提出交易对象、时间、对价、占有和凭证追问。可以列撤销权或拒执相关候选，但官方法源和构成要件保持待核。

### 示例 3：法院正式反馈查到车辆

按正式反馈载明范围记录车辆线索，下一步考虑控制状态、权属负担和处置任务。不得扩张为车辆已扣押、无抵押或必然可变现。
